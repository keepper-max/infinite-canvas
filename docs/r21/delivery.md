# R2.1 本地交付与验收

## 可直接体验

普通账号入口：http://127.0.0.1:5198/__p25/login 。无需输入账号密码，进入隔离示例画布后点击“原生创作助手”，可查看已完成的第一集创作流程、任务详情和保存结果。管理员入口：http://127.0.0.1:5198/__p25/admin 。管理员入口会切换为隔离管理员账号；返回普通体验请重新打开普通入口。

API 3198、Web 5198和独立Agent Worker已启动，PostgreSQL使用r21_isolated，Redis使用独立DB3。恢复与事务回归另用没有后台Worker扫描的r21_regression_isolated。全部为本机隔离数据，不连接生产数据库。

模型使用确定性HTTP替身，只用于A/B/C/D/E及流程、权限和界面验收，不代表真实模型自由聊天质量；工具、PG持久化、审批、CAS、账本和Worker是真实业务逻辑。本地¥2是沿用R2测试策略的合成预算，真实供应商费用为0，未使用R2剩余生产验收预算。

## 泄漏源头及修复

- 提示词将内部协议和用户表达混在一起：保留内部工具指令，增加自然交流规则；问候、讨论与点评不应强制创建计划。
- service持久化message.delta后，原流接口直接发给用户：原事件继续保留；新旧公开流接口均输出安全presentation.updated或必要的画布同步元数据，原始片段不会先闪现。普通回答在单轮完成后再展示，期间显示真实任务状态，不额外调用模型生成总结。
- 原始快照、审批和执行组件直接展示工具参数、结果JSON和原错误：普通快照使用只读展示投影；审批仍使用原id/revision/hash/operationId绑定，原calls和原数据不变。原始完整追踪改为主动请求、服务端管理员校验、会话归属及来源权限校验、字段脱敏。
- plan-service.finish把revision拼入完成报告，模型也可能声称尚未落地的提案已创建：原审计报告保留，用户结果根据完成计划的实际保存回执生成；只有受支持的真实输出形状才显示“已保存”，未知旧数据显示中性提示。
- 执行模式原先把纯问候当成缺少计划，恢复期间还会闪现新会话空态：仅对明确交流且没有写入提案的情况正常结束，创建/修改仍走完整审批；恢复记录时显示准确状态并暂缓发送。面板刷新后仍按原设计收起，重新打开可恢复原会话及草稿。

## 本机草稿兼容与多标签保护

补测确认原面板按用户＋项目共用一条未发送草稿，两页输入可能相互覆盖。新增draft-storage使用每个浏览器文档独立的localforage槽位；sessionStorage仅保存本标签的槽位标识，刷新读取前一槽位，复制标签继承初始内容但首次编辑写入新槽位。关闭重开面板仍复用当前文档槽位。

原项目级草稿只读恢复，不删除或覆盖；新草稿外层格式独立版本1，未知/损坏格式报错并保留源记录，不能当空草稿覆盖。pending原operationId及参数原样保存，未改服务端消息存储版本。写入排队；持久化失败明确提示先复制输入，离开时有未落盘写入则触发浏览器离开保护。旧槽位本轮保留，未增加自动清理或裁剪规则。

## 用户展示模型及界面

服务端userPresentation返回version、messages和tasks；每项包含summary、displayTitle、statusLabel、plan、progressItems、result、safeErrorMessage及technicalTraceRef。结果的资料数量、节点名称、连接方向、保存状态均来自实际回执；固定资料版本使用“资料版本3（固定版本）”等业务说明，不打印revision字段名。

- 普通层：自然对话、完整方案、真实进度/结果、必要费用和下一步操作。用户输入与主动讨论的技术内容保留，不做全局UUID删除。
- 任务详情：默认折叠，显示“阅读《雾港世界观》”“创建节点”等业务步骤及真实状态；费用/预算固定保留在输入区域，定位结果仍使用真实节点ID。
- 技术层：管理员主动打开“管理员技术追踪”；后台同时验证管理员身份、本人会话与现有资料授权，并脱敏密钥/凭据字段。普通账号即使请求自己的追踪也被拒绝；管理员不能借此读取他人的会话。
- 计划层：展示文档名称、固定/最新版本、节点内容说明及来源→目标方向；知识文档修改不会被描述成创建画布节点。无法可靠展示的旧计划不能直接确认，可取消或修改后重新审批。

新的只读接口为GET /api/native-agent/sessions/:id/presentation、GET /api/native-agent/runs/:id/presentation-events；现有快照和事件接口也使用安全投影，原始事件和数据库回执不重写。GET /api/native-agent/sessions/:id/trace是管理员排障入口。

兼容边界：应用控制所需ID、操作ID、审批版本与hash保留；原始steps.input/output、approval.calls和原始delta不再通过普通展示接口提供。依赖这些调试字段的开发调用方必须改用受权trace，不应恢复不安全回退。13个工具、CAS事务、审批摘要哈希计算、计费、运行预算、模型策略及知识正文权威结构未改变，无新增数据库迁移或依赖。
