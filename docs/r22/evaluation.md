# R2.2 对话验收集与评价边界

## 证据类型

真实部分：隔离PostgreSQL、正式HTTP API、独立Redis Worker、JobService/CreditService账本、KnowledgeService、原Approval/CAS和浏览器。替身部分：模型供应商返回文本和Tool Calling协议。供应商费用0；本地显示的Token/人民币均为明确的合成用量及真实账本算法演练，不代表真实模型价格或生产容量。

## 连续对话

隔离《雾港 AI 漫剧》含世界观、林岚、周可、第一集剧本四篇真实文档。第一集测试原稿明确写有“三分钟介绍港口”，评价中的依据来自实际read_knowledge回执；提出的异常声响/矛盾线索标为创意，不冒充原文事实。

- A：你好，我今天不知道做什么。预期无工具、无计划；实际意图Step＋自然响应Step，业务写入0。
- B：你觉得第一集开场怎么样。真实get_project_context→search_knowledge→read_knowledge，再返回脚本替身分析，正式文档原文/哈希不变。
- C/D：反对快节奏→第二个方案且保留职业。前文方案进入后续请求，未创建计划，画布版本不变；用户主动保存带原话来源的创作决定。
- E：按刚才版本修改。明确修改画布文本，知识原稿不改；原计划审批前版本1不变，一次确认后CAS版本2，文本仍为调查员身份。
- F/G：保存后讨论15秒；刷新后再问人设。实际再次提交模型并带授权历史，继续只读讨论；旧保存结果留在原对话位置。
- H：不同账号/项目访问、真实成员撤销、来源软删除。HTTP和上下文拒绝越权；浏览器拒绝后清除缓存展示并保留用户未发送输入；恢复成员后可查询。

实际输入、输出、工具、费用在artifacts/browser-check.json、conversation-transcript.json；详细私有请求快照在Step.input.protocolRequest/contextRequest，管理员受权trace可查，未暴露给普通用户。

## 前后与上下文长度对照

strategy-comparison.json使用相同确定性供应商和同一前文：R2.1兼容路径对“第二个方案，但别改职业”因没有写入计划而暂停；R2.2模型意图判定后正常结束讨论，无审批/写入。这证明控制流修复，不证明模型比以前更聪明。

context-length-comparison.json使用隔离故障语料注入一段长旧话题，实际HTTP模型请求移除完整旧轮，保留真实近期方案及会话摘要，仍在原12k上下文内；原始消息和备份保留，测试后原context原样恢复。短/长语料均可复现，不将注入的旧噪声当真实用户内容或模型能力证据。

## 评价维度

意图与工具合理性以真实工具范围、无写入和审批状态判断；事实依据以真实文档回执和版本比对；连续性以实际提交的摘要、近期消息、用户原话和跨会话决定检查；执行安全以CAS/幂等/撤权/账本/回执恢复检查。不是以出现一个关键词作为“像人”评分。

分析深度、反馈修正质量、自然语言质量、套话频率与真实模型成本目前均未完成真实Qwen主观验收。替身回复只提供固定实验对话，不打“智能/自然通过”分数。人工已检查本地UI可读性、主题和完整交互；真实人类对创作质量的评价仍待用户体验及另行批准的小额真实模型测试。
