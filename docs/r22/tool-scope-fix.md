# Agent 工具参数与操作范围热修

## 根因

生产实际错误为AGENT_INVALID_TOOL_ARGUMENTS。模型把写画布任务路由到suggest_knowledge_relation，并将vibe-…-script画布节点ID作为知识文档UUID。参数校验正确阻断，尚无执行计划或业务写入；不是积分或Token耗尽。参数失败时Run停在model阶段，既有resume仅为tools阶段添加反馈，故用户明确续跑后模型没有收到上一轮参数错误。展示层缺少该错误映射，回落成不可操作的通用提示。

## 修复

- 会话策略增加语义actionTarget：canvas/knowledge/mixed/unspecified。新动作对象不明确则澄清；旧持久化决策保持原行为。画布目标可读取知识，但不开放知识关联/文档写工具，知识目标不开放画布写工具。与既有计划工具范围取交集，不额外扩权。
- 模型请求activeTools和服务端实际回包检查同时约束范围；任何越界或错误参数均停止整个批次，不改写ID、不丢弃部分失败调用后继续写入。
- 明确知识documentId与画布nodeId的不同来源及用途；工具输入Schema/13工具注册名保持，既有模型核验指纹不变。
- 用户明确续跑才添加平台纠错反馈，原operationId幂等、预算批准、未知提交禁止重试、审批/CAS保持。没有自动重试或自动扣费。
- 参数错误提示说明增加预算/查询不能修复，续跑入口提示重新规划及模型积分消耗。

## 实测

28项专项/展示/上下文回归通过，包含真实PostgreSQL错误工具阻断、显式幂等续跑收到反馈、一次审批后仅保存1节点；真实HTTP/独立Worker/Playwright复现参数暂停、纠错提案和审批保存3项通过，pageerror=0。API/Web类型检查和构建通过。完整原业务回归结果及发布记录保存在H:/CodexStorage/shoushou-r223-fix/artifacts。

均为隔离合成模型；未重试用户生产Run，未产生真实供应商费用。Qwen实际创作质量及修正后的真实推理仍需单独费用授权。上线后旧失败任务须由用户明确选择“修正调用后继续”，仍受原预算和保存审批约束。

补充核验：原失败Run实际为advice模式，先前诊断遗漏该状态；模型在建议模式承诺写入，与后续只读工具范围冲突。现由服务端在意图识别后直接返回切换执行模式的提示，停止后续规划模型和工具；真实PG专项4项通过，建议模式动作只调用一次意图识别，0工具/0计划/0写入。原Run仍暂停，未自动续跑。
