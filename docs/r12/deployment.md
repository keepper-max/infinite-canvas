## 新组件与开关

- Web：资料导入面板和原件入口；API：导入路由与服务、KnowledgeService确认事务、存储用量统计。既有生成 Worker 和 MCP无需切换代码协议。
- 新增专用导入 Worker：`npm --prefix server/api run knowledge:import-worker`，运行构建后的 `dist/knowledge-import-worker.js`。它是可信宿主进程，访问专属队列、数据库与对象存储；不能把 Docker socket 挂给公共 API。
- 独立转换镜像从 `server/document-converter/Dockerfile` 构建，无Python、无AI模型。可信宿主以固定命令调用本地 Docker，解析容器不带凭据和宿主挂载。
- `KNOWLEDGE_IMPORT_ENABLED=true` 才注册可用的导入服务；默认不启用。`KNOWLEDGE_CONVERTER_IMAGE=sha256:...` 必须是本地已核验镜像。保存不可变版本标签，不重用或清理仍被 Worker 引用的镜像；启动实际沙箱自检，周期检查镜像存在后才发布就绪心跳。
- 紧急冻结使用 `KNOWLEDGE_IMPORT_WRITES_ENABLED=false`，重启受影响的API/导入Worker进程使配置生效；新上传及新确认拒绝，已完成回执、文档及原件读取保留。不能以整个功能服务关闭替代需要保留的原件读取。

## 发布顺序与前置门槛

1. 用户体验通过并独立授权后，检查生产可信转换宿主的Docker权限、网络隔离、磁盘、对象配额和日志边界；至少为单个解析预留1CPU/512MiB及宿主进程余量，实际容量另做压测。缺少隔离能力时保持格式不可用。
2. 备份数据库、私有对象及现有Web/API产物，恢复到全新目标核对表行和对象哈希。确认备份可恢复后，才启动会自动迁移的新API；本轮隔离预演不能替代生产备份验收。
3. 制作不可变API/Web/转换镜像与SHA256清单。SQL必须LF，逐个核对既有迁移登记与哈希；0049仅新增暂存表和索引，不重置旧数据或改revision、积分、资产引用。
4. 先部署支持0049的新API，导入保持关闭；核验旧客户端知识库编辑、画布CAS、安全插件和原有资产读取，再部署Web和可信导入Worker。
5. Worker完成受限容器自检、镜像摘要检查、Redis心跳后，受控开放导入。用无费用文档验收上传→预览→确认→授权原件下载→检索/关系/画布引用；扫描件、撤权、超限、取消、重复和断网必须拒绝或恢复明确。

## 故障处理与向前回退

- 转换故障：冻结新导入写入，停止接收新解析任务，保留SQL任务和原件；恢复正确不可变镜像与Worker，利用SQL暂存记录补投队列。不要新建operationId盲目重试。
- 确认响应不明：查询KnowledgeService原操作回执；同操作同内容重放返回同文档，不改变正文或版本。
- Web故障：回退Web产物前核对原件接口兼容；旧Markdown入口可保留兼容，但不能关闭新版文档、原件及安全写保护所需API。
- 数据库不执行反向DROP、DELETE或回退已登记迁移；保留0049及所有历史版本、文档、操作回执、原件和账本。只做向前修复，未经单独批准不清理正式数据。
- 不降画布或文档revision、不重新开放旧直库MCP。生成、支付、账户服务沿用原发布保护；本轮不构成付费模型或真实人民币结算验收。
