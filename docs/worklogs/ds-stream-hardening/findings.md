# 实施与副作用复核
- 原请求只有158字符、不完整JSON；供应商记账3秒而客户端最终60秒中止。旧请求未保留原始流结束元数据，补丁不能逆向恢复缺失正文。
- 实际SDK本地回放已复现：DONE后HTTP不结束会挂起；正常SSE、UTF8拆分能解析；已明确的SSE JSON坏包/缺finish且EOF会立即报错。
- 新适配层仅拼好站Agent推理使用，价格/账单/媒体生成/其他模型保持原路径。没有新增超时、重试、大小或并发阈值。
- 字节观测位于fetch解压后、SDK前，不是TCP/TLS抓包。保留原始响应体字节及响应头，不二次改写模型文本/工具参数。仅一个上游reader，不用tee或后台全量缓存。
- 使用现有eventsource-parser 3.1.1，已核验MIT许可证并在package/lock根依赖中显式锁定；没有新下载、版本升级或C盘缓存。
- 提前收尾仅在stop/tool_calls、合法整数用量、DONE齐全且无解析/上游错误、身份混流或多choice时发生。缺用量/缺finish/截断长度/数据异常保留原请求待核查；不生成缺失JSON、不猜测用量、不以账单冒充结果。
- 新增include_usage请求选项，实际发送的stream_options及最终请求hash均走既有持久化路径。严格语义/工具schema与服务端权限审批仍在原链路执行。
- 新providerStream记录计数、时间、枚举/布尔状态和用量数字，不存正文/思考/工具参数/错误原文/凭据。里程碑写入串行，等待最终flush；不会每chunk写库。元数据持久化失败不能掩盖成功路径；异常路径保留原供应商异常不让二级诊断错误覆盖根因。
- 历史回执读取不会新增供应商请求。未知结果依旧停在核查，不释放未知费用预留。完整协议但语义半截JSON仍失败，不修改画布；真实已产生的费用正常结算，不能伪称零扣费。
- userPresentation不返回providerStream；现有管理员trace入口可读取，新字段不会重新显示到前台。
