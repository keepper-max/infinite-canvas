# AutoCut 素材列表与两次任务失败修复

## 根因

- 素材区固定最大380px，长文件名还会多行换行；素材多时将创作意图与开始按钮推到视口外。按视口高度限制列表、内部滚动、长文件名单行省略且保留完整title，并收紧现有间距；不改素材数量限制和提交行为。
- 11项真实视频的FFmpeg处理逐项通过。第4项本地FunASR 1.3.22记录empty speech，返回明确的空text和timestamp数组；桥接脚本要求sentence_info，因此把无人声当作识别失败。仅该明确形状返回空字幕，缺少结果、非空文字缺少时间戳仍拒绝。
- 另一任务尚未发起plan-v3，仅有素材理解调用。原模型返回evidence数组，元素为text/segment_start/segment_end对象，旧校验只收字符串，因此被通用Zod错误误标为剪辑方案格式错误。新增严格响应解析，兼容文字、文字列表及明确的句子引用列表，保留引用和时间，拒绝额外字段、错误类型、越界证据；提示词补全类型和schema。首次粗剪source-only及字幕映射校验不变。
- ASR子进程真实异常改为ASR专属错误，不再显示媒体格式错误。识别及模型缓存复用、调用幂等、计费和权限不改。

- TypeScript 9项测试通过，无跳过：文字/结构化证据、非法类型和越界拒绝，以及已有首次选段、字幕源/成片坐标、ASR排队和取消回归。
- 生产既有CPU容器只读下载原失败视频，用内存中的候选Python脚本完成真实FunASR回放：第4项通过、0字幕。未覆盖生产脚本或执行任务重试，诊断临时素材已在finally清理。
