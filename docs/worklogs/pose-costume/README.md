# 姿势与服装参考库接入记录

## 入口与实现范围

顶部导航「姿势与服装」可直接进入；在当前画布点击时保留该项目，从其他页面进入默认项目并自动打开参考库面板。已有节点复用，无节点时按当前编辑权限创建，保存沿用画布链路。也可使用画布「新建节点」→「姿势与服装参考库」。按用户明确的个人非商用试用需求，本地开发页面（localhost / 127.0.0.1 / [::1]）启用原站图片按需浏览、逐张参考导入及姿势深度图切换；公开发布构建继续保留图片授权门控。使用现有节点注册机制，无新账号、渠道密钥、计费服务、模型网关或后台队列。

- 查询完整固定版本目录：中英文名称、关键词、编号、多词搜索，分类、发长、原目录/名称/编号排序、扩展分类、收藏、逐批加载。人物只使用源数据已有的人脸/造型、发长信息，不增加瞳色、肤色等推测标签。
- 人物、姿势、服装三个参考位置；人物支持图库、画布、当前项目云端资产和上传。姿势/服装支持自有图片、画布及资产替换；姿势/服装原站图片在本地个人试用中可逐张导入；公开发布环境保持门控。
- 组合与收藏保存在参考库节点 metadata，随现有项目画布保存；仅保存少量编号、提示词及不可变资产引用，不保存目录全集、图片或 base64，不使用 localStorage 保存业务数据。
- 参考图片按实际「人物、姿势、服装」顺序提交；无人物图时按两张图重新编号。角色职责同时写入提示词与任务 trace。模型必须声明 i2i 和足够的 maxImages，否则阻止提交，不截断图片。
- 复用平台受管任务和整数积分账本；生成前保存画布，并传 projectId、nodeId、持久化幂等 operationId。保存选图、模型、提示词、参数、来源编号与视角快照到 trace，现有 worker 将 trace 和输入资产版本写入结果资产 provenance。
- 面板重新打开或刷新后查询原任务；丢失提交响应时复用同一 operationId 恢复。显式取消调用已有 cancel API；关闭面板只停止等待。仅对后台声明 retryable 的 failed 任务开放原任务重试。
- 已交付结果以确定的结果节点 ID 添加图片节点，复用后台资产版本，不二次上传；重复恢复不重复添加。支持并排与滑杆对照，对照使用生成当时的实际输入快照。结果图片工具栏可「继续搭配」，创建可继续编辑的组合节点。

## 已核查的主链路与副作用

- `repository.syncAssetLinks` 递归收集 metadata 中 assetVersionId，核对资产属于当前项目，并纳入现有引用保护。新增嵌套组合没有绕过这一校验；跨项目资产仍会被拒绝。
- 资产 API 校验项目成员、写权限、配额与文件元数据。图库导入按「当前项目 + 固定目录版本 + 素材 + 视角」查找已有版本，同会话并发导入合并；自有上传按 SHA-256 复用项目现有版本。
- 现有 JobService 校验项目编辑权限和节点存在性，按项目幂等号去重，再由现有账本预留和结算整数积分。未增加新的预算、超时、重试次数或并发上限；一次任务仍沿用现有失败/取消/计费待核验行为。
- 通用画布任务事件会把完成事件交给旧媒体恢复逻辑；仅排除本参考库节点，由专属快照恢复逻辑交付结果，避免写错状态。未改其他节点行为。
- 关闭窗口不保证撤销后台任务，UI 明确提示。计费待核验和余额不足不展示为 0 积分，保留任务编号供刷新恢复。
- 当前收藏和组合随本参考库节点保存，属于项目共享数据；没有引入独立的个人跨项目收藏同步。
