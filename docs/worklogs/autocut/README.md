# 守守画布 AutoCut：审计、实现与验收

代码位于正式仓库，本轮未提交、推送、部署或修改生产配置。既有 DeepSeek 工作区改动保持原样。独立入口为 `/autocut`，画布节点为 `autocut:editor`，不依赖漫剧角色、剧本或分镜。

## 当前系统审计

- 前端：`web/package.json`、`web/src/router.tsx` 证实 Vite / React 19 / React Router / Ant Design 6 / Zustand。正式仓库不是 Next.js，不套用附件目录的 Next.js 约定。节点通过 `web/src/lib/canvas/node-registry.ts` 注册。
- 权限与数据：`server/api/src/app.ts` 使用 Hono、登录 Cookie 和来源校验；`project-access.ts` 校验成员和已删除项目；PostgreSQL 为权威存储，Drizzle 与原生 SQL 并用。AutoCut 额外按工程创建者隔离；成员编辑权限被撤销后，Worker 停止。
- 资产：`asset-service.ts`、`object-storage.ts` 已提供签名直传、不可变版本、文件大小/声明哈希核对、配额与引用保护。AutoCut 复用这些接口，浏览器使用增量 SHA-256，Worker 再流式计算真实 SHA-256；不以外部 URL 作为剪辑输入。
- 生成与计费：`model-gateway.ts`、`job-service.ts`、`billing-service.ts`、`credit-service.ts` 已有模型目录、任务预占、提交回执、用量与人民币结算。RunningHub / 国际站 / Token360 / 火山适配器存在，但原先文本请求没有发送视觉关键帧；本次仅在 `trace.workflowKind=autocut` 时扩展消息负载。
- Agent 与队列：`native-agent-worker.ts` 的独立 Runtime 已存在，但付费适配器绑定原对话 Run/Step 和知识审批，不适合拿假对话记录套接剪辑。AutoCut 使用同样的独立服务端运行方式及现有模型任务系统，以专用 BullMQ Worker 执行固定分析/规划/渲染工具链；没有 Codex / CLI / 开发会话运行依赖。尚未向原生助手对话工具表新增 AutoCut 工具。
- 视频：`composition-service.ts` 已有漫剧合成，但画面拼接不自动保留视频原声，静态图片也没有独立输入路径。保留其稳定流程，新增 AutoCut 媒体执行模块；复用同一 FFmpeg 可执行文件和 S3 资产基础设施。
- 部署：现有 API 镜像包含 FFmpeg 与文泉驿字体，普通 Worker 同时承担生成/转存/旧合成。新剪辑任务不放入这些请求或合成队列，而是进入 `autocut-jobs`。只读核查通过指定 `shoumiren-production` 入口完成，实际应用主机为 24 核、约 62 GB 内存、根分区剩余约 82 GB；并非公网 ECS 跳板机。该信息是资源快照，不能证明负载下的稳定性。

## 实现架构

1. 用户从工作台上传或选择已有平台素材，创建独立剪辑工程；画布节点把直接上游的云端资产版本交给相同接口。
2. API 只做身份、工程、不可变版本、预算与乐观锁校验，创建持久化任务并入队。Worker 检查权限、取对象、校验字节与真实 SHA-256。
3. FFprobe 获取实测元数据，FFmpeg 检测场景突变/静音并抽取 JPEG 关键帧。粗分析最多采样 20 帧/素材，保留全部测得的镜头边界；不是逐帧向模型上传视频。
4. ASR Provider 当前为已配置的本地 FunASR CPU 适配器，必须使用本地 ASR/VAD/标点模型路径；无运行时下载。保存实测句级时间戳，置信度未知记 `null`。未配置时明确失败，不把空字幕冒充识别完成。接口位于 `autocut/media.ts` 的 `AsrProvider`；云 ASR 的托管计费接入仍待补齐。
5. 视觉 Provider 为 `AutoCutModelProvider`。当前发送“关键帧 + 实测时间 + 转写”，不假定供应商接受 MP4。模型输出片段摘要、依据、置信度，按分析版本缓存；本地预处理与 ASR 有单独缓存，失败后可复用。
6. 规划模型只输出受限的素材序号和选段，不生成任意 FFmpeg 命令。`planner.ts` 负责 ID、资产解析、总时长和连续排布。真实测试曾发现模型伪造 UUID/混淆版本 ID，因此废弃首轮直接要求完整 Timeline 的协议；旧任务不能静默切换新协议并重新收费。
7. `contract.ts` 对工程归属、资产版本、片段边界、画面连续性、音轨/字幕范围和转场执行第二层校验。首次字幕由程序映射实测 ASR；字幕专用修改范围强制保留画面与音轨。
8. Renderer 按片段处理视频/图片及原声，拼接、混音、烧录字幕并产出真实 MP4。成片登记为平台资产，保存来源版本和工程 revision。每个保存版本不可变，撤销及恢复不改写旧记录。

完整最终工程 Schema 见 [timeline.schema.json](timeline.schema.json)。时间均为整数毫秒，区间统一为 `[source_in, source_out)`；图片入点为 0，出点表示停留时长。输出为 720 级别的 16:9 / 9:16 / 1:1、25/30 fps、H.264/AAC MP4。`target_duration` 是编译后的实际工程长度，用户期望时长另存于任务输入；不能用目标时长填充不存在的素材。

## 任务、预算与存储语义

- 已确认资源边界：全局并发 1、FFmpeg 2 线程、每任务 30 分钟、每项 500 MB / 30 分钟、每工程 20 项素材。队列不自动重试付费调用；取消终止当前媒体进程并向模型子任务发取消请求，已被供应商接受的费用不会凭空撤销。
- 阶段包含排队、预处理、理解、规划、费用结算、渲染、上传、完成。数据库为状态权威，队列交接有恢复扫描；崩溃遗留的运行任务转为可核查失败，保留原模型请求。PostgreSQL 会话锁防止重复执行，锁丢失会终止处理。
- 每个模型调用先保留管理员配置的保守人民币上限；不得超过用户本任务确认预算。子任务走原 JobService/积分账本。供应商账单未落定则等待现有结算；未知/异常/余额不足停止。显式重试复用已有 generation job，不自动新建收费请求。报价配置必须覆盖模型上下文、图片、输出、平台加成与取整，不能拿经验报价冒充保证。
- 原始对象不覆盖，任务工作目录独立；正常结束即清理，崩溃目录超过 30 分钟且任务不再活动才清理。Windows 默认临时目录在 H 盘。源素材和成片通过 `asset_links` 保护，普通画布保存不会清掉这些引用；归档工程可释放该工程引用，保留文件与工程记录供后续管理。
- API 不接受媒体 URL；FFmpeg 使用参数数组、禁止 Shell、限定协议和解复用器。模型只能提供受控 JSON。画面/转写是数据，不是工具指令；密钥继续仅在既有服务端配置中。

## 验收结果与边界

真实记录见 [acceptance.md](acceptance.md)，开源审查见 [components.md](components.md)，启用配置/API/迁移见 [deployment.md](deployment.md)。

- 已完成并测试：真实 CPU 语音转写、关键帧模型分析、受限选段规划、Timeline 编译/校验、真实带字幕/原声 MP4、工程保存、浏览器字幕修改刷新、裁切撤销、真实上传/排队取消、PostgreSQL 隔离和 Redis 全局并发。
- 已完成但未充分验证：完整 Linux 容器部署、所有输入格式组合、长片/损坏媒体/磁盘耗尽等故障矩阵。画布节点的独立上游导入、任务启动/取消与显式保存已通过浏览器验收，成片回填、取消退出加载态及刷新恢复也已通过真实渲染与浏览器验证，完整 Linux 后台容器联调仍待完成。模型质量主要由自制口播和独立图片验证，不能外推至所有场景。
- 尚未实现：云 ASR 托管计费、重点候选二次精分析、词级对齐、说话人分离、主体追踪、批量多条成片、音乐自动匹配、原生助手聊天工具接入。后两项属于 P1 或后续集成，不能把当前“单工程单成片”说成多条自动成片。
- 需要配置或验收：CPU ASR Worker 的 Linux 运行镜像及本地权重、已实测支持图像输入的目录模型、保守报价/输出 Token 上限、容器 CPU/内存和磁盘配额、生产发布审批。当前未部署，不宣称线上用户已可用。
