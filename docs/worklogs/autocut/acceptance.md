# AutoCut 实际验收记录

## 已完成并实测

- 自制素材：Windows 本地 TTS 朗读三句说明，中间加入停顿；FFmpeg 生成自有图形画面并封装为 15.28 秒 MP4。不是客户私有素材，也没有把模型替身冒充真实模型。
- CPU FunASR 返回四个实测句段：150–2125、4770–6290、6690–7975、10360–12895 毫秒，含中文转写，置信度未知记 null。没有按字数插值时间戳。
- 外部模型实际接收 JPEG 关键帧和转写完成分析/选段。第一次直接让模型生成完整 Timeline 时出现伪造 UUID、混淆 asset/version 和错误总时长，校验器拒绝。随后改为“序号选段 → 程序编译”协议，复用原分析及 ASR，正确生成 7315 毫秒工程。
- 实际输出 `H:/CodexStorage/autocut/poc/real-ai-output.mp4`，1280×720，H.264/AAC，容器时长 7.331 秒。四段来自原视频真实区间，带原声和烧录字幕。再次对成片执行真实 ASR，四句含义完整保留。首次样片音视频起点差约一帧；最终渲染器已增加显式 PTS 归零，相关真实媒体回归通过；仍需真人口播长片人工验收，不能只凭文件时长认定感知同步完美。
- 独立视觉验证不提供答案，仅发送自制图片：模型返回 `AUTOCUT Q7K9`、蓝色背景、黄色矩形、无真人。证明该路线确实消费图像，不能只靠语音内容作答。
- 真实媒体自动化另验证视频原声、图片停留、外加音轨、字幕以及取消实际 FFmpeg 子进程；资产下载校验实际 SHA-256，内容改变时拒绝使用缓存。

## 资源实测

本地 Windows 同时运行真实 FFmpeg 与独立 Hono/PostgreSQL API：一次已缓存分析的短样片渲染约 3.75 秒，成片约 1.78 MB，渲染临时产物约 3.60 MB，素材约 1.47 MB。87 次真实健康请求的 P95 约 6.96 ms、最大约 154.22 ms。

仅取得两个进程样本：采样工作集最大 154083328 字节（约 147 MiB），观测到一个 FFmpeg 进程，采样累计 CPU 约 2.59 秒。这是稀疏采样的观测值，不能称为可靠峰值、完整 CPU 总耗时或服务器容量上限。生产只读快照为 24 核/约 62 GB 内存/根分区剩余约 82 GB；没有在生产同时发起剪辑压测。

最后成功续跑的旧报告中 `totalMs=3177`、`analysisMs=4` 表示已缓存后的那次尝试，不是首次转写/规划全流程耗时。最终实现已区分单次 `attemptMs` 与含重试等待的 `wallMs`，并为后续分析记录保存 ASR 耗时；旧记录缺失的测量不回填为虚构结果。
