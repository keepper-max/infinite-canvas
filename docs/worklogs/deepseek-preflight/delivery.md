# DeepSeek专项修复交付

## 结果
仅针对拼好站DeepSeek修复，没有切换供应商或替换为其他模型。已获追加发布授权，v0.16.50完成commit/push/部署；当前用户任务和费用不变，正式结果见ops/releases/v0.16.50-deepseek-preflight.md。

## 改动
- native-agent/model-clock.ts：阶段时钟，仅DS最多预检60秒+推理60秒，仍受原Run截止时间限制；其他模型不变，重复回调不能延长。
- native-agent/service.ts、model.ts：可信内部提交回调启动推理时钟，记录新步骤transportBudget；不修改历史回执审计、不把回调写进请求正文或哈希。
- pinhaozhan.ts：两个新鲜只读检查并行，任一失败取消另一个，不跳过价格或账单校验、不增加推理重试；记录每个端点起止与真正失败来源。
- native-agent/paid-model.ts：预检全部成功后重新验证身份/知识权限、取消和平台预算，之后才允许提交。保留原Job/账单/operationId与结果落盘流程。
- native-agent/presentation.ts：明确当前轮次未提交，不把此前已完成轮次的真实计费描述为零扣费。
- 新增两组针对性测试，更新工作记录与待验收；无需数据库迁移、依赖变更或知识正文调整。

## 已运行验证
- 28项唯一针对性自动化测试通过，API类型检查及构建通过。
- 真实PostgreSQL、真实HTTP供应商替身，7场景：慢预检成功、价格失效、账单403、取消、权限撤销、预检超时、提交后推理超时。缩放时钟5秒仅用于隔离实测；生产边界60秒另有Date/setTimeout模拟验证。
- 正常场景只提交1次、计1个测试积分，重复查询/drive不重复调用；提交前失败0提交/0扣费/预留释放；提交后超时保留待核查与测试预留，不自动重发。
- 生产服务器独立进程仅执行候选只读预检：两项同时开始，11.809秒完成，真实推理0次。此项不等于真实付费模型端到端验收。
- 未测试真实付费推理、物理设备、Windows中文输入法；本次没有前端布局改动。

## 下一步发布与安全边界
- 获得发布批准后按既有备份恢复、不可变制品、维护/队列、后端先于Web、健康核验流程部署；无需迁移，不重构部署体系。
- 业务源码仅改后端，发版时按既有流程统一Web/API/Worker版本信息。真实付费验收需另外确认预算，不自动复用旧失败即停测试额度。
- 原预检失败任务可以经用户明确操作继续；已完成意图识别不需要作为新任务再次执行。提交状态未知任务仍只核查原回执，不能重试生成。
- 回滚保留所有任务、费用和回执，只恢复镜像；不改revision、不清理预留。旧版本重新出现共用60秒的行为时应停止受影响的DS新请求，而非关闭计费校验。
- 外部网络全部地址持续不可用仍会安全失败。本修复消除计时挤占，不承诺供应商网络或服务的永久可用性。
