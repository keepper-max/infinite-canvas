# AutoCut P1 功能与部署记录

当前生产已发布 `v0.16.53`，代码 `ae0b50ff460c`。正式部署与Linux/账号冒烟结果见 `ops/releases/v0.16.53-autocut-p1.md` 及本目录 `production/`。以下保留先前开发阶段的交付和未验收限制；目标剪辑软件兼容性仍未验收。

本轮按用户后续决定执行“P1 不用验收，暂时只做功能”。新增功能留在工作区，P1 默认关闭；没有提交、推送、部署，没有写生产数据库或生产配置。当前交付是开发版本，不能据此宣称浏览器交互、真实视频质量或剪辑客户端兼容性验收通过。

## 已实现的链路

- `/autocut` 的精修入口指向 `/autocut/editor?edit=<工程ID>`。主轨、叠加轨、原声、音乐、字幕/标题共用 v2 Timeline；支持拖动排序、边缘裁切、播放头、磁吸、多选、分割、复制、删除、撤销/重做、明确保存和历史恢复。
- 浏览器直接读取已有鉴权媒体接口，用源时间和同一效果解释器驱动 Canvas 与显式音轨。操作不触发整片重渲染；字体、色彩、锐化及滤镜显示近似提示，可提交单片段低清渲染。预览窗口不会写回正式工程或替换画布成片；生成前会先保存当前尚未保存的编辑。
- 变换、位置/缩放/旋转/透明度关键帧、缓动、亮度/对比度/饱和度、静态模糊/锐化、速度、音量效果和边界转场均有严格参数校验。主轨总时长扣除转场重叠；原声在转场区间配对淡入淡出。
- 受限 `effects-v1` 独立阶段只建议所选片段/字幕的预定义效果，不扩大原 v3 选段协议。只提交选中目标的元数据/已有候选摘要或所选字幕，手动编辑与固定预设不调用模型。AI 不支持改写选段、轨道时序或自然语言修改转场，界面保留模型的不能实现说明。
- 工程导出支持 SRT、OTIO、FCP7 XML 与剪映 SDK 草稿的 ZIP 生成。包含原始 Timeline、兼容说明、素材清单、SRT，以及可选使用素材。下载沿用签名机制；流式 ZIP、分片对象上传不将 5 GiB 整包载入内存。

## 关键代码

- `server/api/src/autocut/p1/runtime.ts`：共享类型、插值、源字幕映射、剪辑操作和预设。
- `p1/contract.ts`：v2 严格 Schema、资源/归属/时间/锚点校验、默认关闭开关。
- `p1/render.ts`、`p1/preview.ts`：FFmpeg 合成与临时低清窗口。按实际 FFmpeg 能力选择滤镜脚本参数；使用显式中文字体文件；中间成片及时释放，音轨逐段混合避免一次打开数百解码器。
- `p1/operations.ts`、`scripts/autocut-p1-export.py`：无付费素材准备、导出适配与受限 ZIP。
- `p1/effects-planner.ts`、`autocut/executor.ts`：独立效果阶段、渲染/准备/导出任务衔接与取消恢复。
- `web/src/pages/autocut/editor/`：页面、时间线、预览与属性检查器。
- 原 `service.ts`、`routes.ts`、`object-storage.ts`：复用所有权/CAS/版本/队列和人民币账本，增量提供 P1 接口与流式文件上传。

## 兼容性与依赖

没有引入第三方完整剪辑应用，也没有替换 ASR、模型供应商、Agent Runtime 或账本。本轮没有新增数据库迁移。

- [pyJianYingDraft](https://github.com/GuanYixuan/pyJianYingDraft)：0.3.1，审查 commit `1e228479dda361e312e85f6037002346cf6dca9a`，Apache-2.0。实际使用 `DraftFolder`、`TrackSpec/append_track`、`VideoSegment`、`AudioSegment`、`TextSegment` 与关键帧 API。视频原声先由 FFmpeg 提取为临时 WAV，再作为独立音轨打包。
- [OpenTimelineIO](https://github.com/AcademySoftwareFoundation/OpenTimelineIO)：运行版本 0.18.1，Apache-2.0；FCP XML 使用 `otio-fcp-adapter` 1.0.0，Apache-2.0。OTIO 数据写入与 FCP7 适配器单独调用。
- [pyCapCut](https://github.com/GuanYixuan/pyCapCut)：审查 commit `ec61408d9f039c4045f946370bb35746b89b2479`，0.0.4，仓库未找到许可证且包元数据没有许可声明。没有安装、复制或启用该依赖；适配分支不构成可用性证明，需明确许可及独立 SDK/客户端适配后才能开放。
- 剪映本机 11.5.0.14471 未打开测试；CapCut、Resolve、Premiere 未做测试。所有导出格式的 `verifiedClientVersions` 均为空，前端和包内均标明实验性。

导出有已知降级：原生转场、滤镜、字幕动效、复杂音量关键帧及缓动未完整映射；OTIO/FCP7 的字幕独立交付为 SRT，重叠素材可能拆到不同轨道。素材原始字节保留，目标软件的视觉一致性、变速和静音解释仍须另行核验。不包含素材时，需自行重关联；剪映分离原声还需对应 WAV。

## 本地启用与后续发布边界

本地开发可为 API 和 AutoCut Worker 同时设置 `AUTOCUT_P1_ENABLED=true`，沿用现有 V1 配置。导出 Worker 另设 `AUTOCUT_P1_EXPORT_PYTHON` 与 `AUTOCUT_P1_EXPORT_SCRIPT`；API 配置相同可用性开关以显示导出入口，不能把配置存在当作运行验证。字体可用 `AUTOCUT_FONT_FILE` 指向现有中文字体文件。

导出依赖使用单独 venv，锁定清单为 `server/api/requirements-autocut-export.lock`。该清单固定源 commit 和包版本，尚未提供 Linux 全平台 wheel 哈希锁；Linux 安装还需要 `libmediainfo0v5`。可选配方 `Dockerfile.autocut-p1-export` 继承显式不可变 CPU Worker 镜像，并保持 P1 开关默认关闭；本轮没有构建它或宣称 Linux 导出通过。

以后若授权发布，应先完成 Linux 依赖/镜像实跑、必要客户端兼容性及资源门禁，再复用 V1 发布备份、管理员/普通账号与权限/计费检查流程。保持原并发 1、FFmpeg 2 线程、任务 30 分钟、20 GiB 临时盘和容器硬限。

关闭新 P1 任务时保留已经保存的 v2 revision、素材和账单；允许在 P1 版本代码保留期间恢复到先前 V1 revision。已经产生 v2 工程后，不应只回滚到完全不识别 v2 的旧二进制并把任务继续交给旧 Worker。需先停收/暂停队列并保留能识别 v2 的读取路径，确认活跃任务处理方式，再回滚服务。禁止删除 v2 用户数据来“兼容”旧版本。

本次不扩大至新框架替换、ASR 优化、GPU 或新云服务。下一步是由用户审阅功能代码并在明确需要时另行启动验收；当前不能作为生产上线候选通过证明。
