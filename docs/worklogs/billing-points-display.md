# 全站模型计费积分展示修复

本文件记录积分展示修复；本轮用户已授权提交推送与部署，实际发布状态见ops/releases/v0.16.55-billing-points.md。生产原倍率保持1.2、100积分/元、逐笔向上取整，不调整充值、余额、预算上限或历史账单。

## 已变更

- 项目AGENTS.md加入必须规则：模型费用、预算与消耗统计统一积分；已结算直接读取账本，不在浏览器再次乘1.2；未知费用明确待结算。
- AutoCut原工作台、P1精修、画布节点与Agent管理预算改为整数积分。旧cents字段保留，现行1分和1积分数值相同，1000积分仍等于原10元上限；预算不额外加价。
- AutoCut详情增加credit_points/credit_status查询，精修费用栏区分已扣/待支付/待结算，不再展示cost_cny。
- 后台概览、用户消耗、流水及分组汇总按逐笔charged积分统计；未支付不计已扣，待处理数量单独提示。后端原始供应商字段保留核账与兼容，前端不再拿它们作为用户价格。
- 充值支付金额、充值经营统计、准备金、汇率配置和人工原币核账输入保留真实资金单位；核账输入注明“非用户报价”。

## 实现与验证

公共展示入口为web/src/lib/credit-display.ts，使用BigInt保持大额精度，缺失字段不伪装0积分。只读积分投影位于operations-service.ts和autocut/service.ts，没有修改CreditService/BillingService扣费函数或生产数据。

7项相关回归通过、无跳过，覆盖逐笔小额积分求和、未支付排除、外币已结算积分、未知/零值和大整数、账单原记录不变、账户显示和原AutoCut权限链路。API/Web类型检查与本地Vite构建通过，仍有既有大chunk/混合导入提示。

部署时先更新API查询字段再更新Web。旧API缺少积分字段时新UI会显示待结算，不回退为供应商原价。尚未执行本轮线上或浏览器交互验收。
