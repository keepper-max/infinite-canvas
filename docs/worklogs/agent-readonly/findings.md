# 根因与副作用

- 原请求明确只读且禁止创建或改动，供应商已经返回正确统计；分类却为action/canvas。
- service自动提升为execute；executeTools空调用转入reviewOrSeal，后者补一次规划，继而AGENT_NO_EXECUTABLE_PLAN。
- 不能直接让所有“无工具调用”都完成：会使真正的写入请求在未生成计划时伪报完成。
- 当前修复在新分类及加载历史分类时收窄能力；历史模型字节、hash、账单和原操作ID保持。恢复回执额外核对当前有效工具范围，不能借旧工具清单绕过只读约束。
- 只读语义由分类器处理；确定性限制仅识别当前指令首部明确只读、末尾明确禁止改动的形式，不把标题或引用中的“只读”当成任务意图。

- 进一步收紧确定性限制：末尾必须是“禁止创建与改动全部内容”或“禁止写入任何内容/数据”这类全局禁止；“先读再创建，但不要改已有文档”仍保留写入意图，不能被误判为已完成。
- 旧任务恢复原本无条件把tools阶段转回model，是另一处额外计费入口。现在仅在原错误为无计划、当前有效分类read、最后模型有完整回答且无调用、无计划/审批时保留tools阶段直接收尾；任何不完整或有待执行内容的情况保留正常恢复路径。
- 原测试库启动后执行异常关机恢复，未重置或中断。另建127.0.0.1:55486临时内存PostgreSQL，使用已验收49份迁移隔离验证；原库随后自行恢复就绪。
