# 科技树卡顿定位与本地优化

本地优化完成后，用户另行授权commit、push与部署，现进入v0.16.26静态发布；最终生产核验与回滚证据另见ops/releases/v0.16.26.md。优化版预览：http://127.0.0.1:4411/lab/polytech-tree/ 。此处仅针对科技树，不把结论扩展到画布工作台或API。

## 原因与证据

- CPU：3862个节点每帧重复计算自转、四元数、矩阵并整块上传GPU，静置也如此；高刷新率屏幕进一步放大总开销。拖动时还全量投影/排序知识名称，pointermove逐事件遍历实例拾取。
- WebGL纹理：初始为全部名称生成图集，实测基础纹理总量240.375MiB，包含mipmap约320MiB；仅展示24个名称仍占用全部图集。此为纹理尺寸估算，不是进程或设备总显存测量。
- 网络：线上主块请求Accept-Encoding:gzip后无Content-Encoding/Vary，原始长度2,000,231字节；解释冷启动慢，不解释持续交互卡顿。本地配置补gzip，未修改线上配置或部署基线。

## 最小作用域修复

1. polyhedra.ts继续用5类InstancedMesh、同一材质和旋转/显现公式，改由顶点Shader执行；CPU矩阵仅在过滤/聚焦等可见性变化时上传。法线同步旋转，选中/悬停保持原样。
2. 拾取先用外接球剔除明显无关项，再对候选按GPU当前相位做真实网格相交检测，并非将命中近似成球。鼠标悬停合并到每个实际渲染帧，点击仍即时准确拾取。
3. labels.ts保留字号、优先级、投影和矩形避让，仅维护当前可见名称DOM池；时代标签保留小型图集。优先级分组按需投影、填满原名称预算即停止，不删数据或减少预算。
4. main.ts缓存ResizeObserver提供的画布尺寸，静止时代标签不重复更新属性；不可见/后台画面不绘制，恢复后继续。卸载和bfcache恢复同时释放/重建DOM名称层。

## 单次同机对比

Chromium1243，真实NVIDIA RTX2070/D3D11，1440×1000，同一Vite源码服务。两个阶段分别为约6秒静置、40步相同轨迹拖动；没有CPU降速，不能代表低端手机。基线本机已约144fps，优化后仍约144fps，不宣称提高用户设备的FPS。

- 静置每帧脚本：1.757ms → 0.372ms（约降79%）；每帧CPU任务2.106ms → 0.744ms（约降65%）。约6秒属性上传214,827,228字节 → 0。
- 拖动每帧脚本：3.886ms → 1.643ms（约降58%）；每帧CPU任务4.364ms → 3.056ms（约降30%）。观察阶段属性上传约160.4MiB → 24KiB（两个阶段时长略有差异，不当作定量带宽基准）。
- WebGL基础文字纹理240.375MiB → 0.75MiB（只剩时代图集）；可见DOM名称仍由浏览器合成，占用未计入此数字，不能称总显存仅0.75MiB。
