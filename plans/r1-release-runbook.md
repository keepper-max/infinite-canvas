# R1 正式发布与安全回滚手册（操作提案，未在生产执行）

当前不满足正式发布条件。以下步骤只有在阻塞项解除且用户明确授权具体发布窗口后才可执行；本轮没有连接生产、备份生产、迁移、部署、重启或切换 MCP。

## 发布顺序

1. **封存与授权。** 审阅 R1 清单、全部未提交差异及用户无关修改；以候选源码文件哈希、依赖锁、API/Web/插件/MCP/Agent 制品校验和为准。当前 VERSION 仍为 v0.16.31，不擅自提交/tag/推送；正式版本、批准源码和提交范围另审。缺制品或源码不一致即停止，不能现场从混合工作区重建。
2. **最小生产核查。** 获批后只执行 R1 readonly-scope 和 SQL 提案，经 `shoumiren-production` 确认真正应用主机、`/opt/infinite-canvas-releases/current`、PG/Node/存储参数、旧 API/Worker/MCP/自动化/缓存与调用方。未知写者、版本漂移、缺迁移或坏图未处置时停止；不读正文、不擅自全库扫描。
3. **用户与写入冻结。** 提醒用户保存草稿，禁止旧标签页继续保存。停止已确认的旧直库 MCP/预览 Worker/自动写者，冻结新的生成提交，按供应商请求 ID 处理已在途任务，不能丢弃或盲重放。将经批准的入口网关切为维护模式，验证知识 CRUD、画布、任务提交、素材/账户变更等写路径均受控，正常登录/退出/授权读取保留。`CANVAS_WRITE_MODE=read-only` 只管画布，不能当全站停写开关；私有 MCP 是独立入口，须单独 read-only 并阻断旧进程。直连 API/数据库或旧 Worker 仍可写时不得继续。
4. **备份与恢复验证。** 写冻结后执行获批的 PG 一致性备份；角色/权限、扩展、迁移表和恢复所需元数据单独受控保存。对象按同一冻结点备份/快照，保存 key/version/hash/metadata 清单；发布目录、镜像、插件与 MCP 产物也保留。先恢复到全新隔离目标验证表行数/hash、知识版本/关系/来源、素材对象和权限。备份失败、无法恢复或仍有未知写入，保持维护并取消窗口，不继续迁移。
5. **增量迁移。** 0045→0046→0047 顺序执行，先对比1–44已应用校验和，绝不重写迁移记录。当前 runner 每文件一事务并持有同一 advisory 锁；API/Worker 启动也自动迁移，因此不能在备份/授权之前“只读启动新 API”。逐项记录成功、时间与锁等待；0046 的表/索引创建与数据规模有关，本地耗时不是生产锁预算。出现失败停止后续流程，保留已成功迁移及迁移表，不反向 DROP。历史异常修复独立审批，不能为放行自动去重。
6. **安全制品与客户端切换。** 发布已审阅 API/Web，先保持所有写入口冻结；部署 Markdown 1.1.1 及真实 registry 包，并对持久化 source 的已安装客户端执行显式升级。记录升级前启用状态，既有 updatePlugin 会启用插件，升级后按用户原状态复核；不能只刷新网页或更换 CDN 文件就宣布安全。旧1.1.0不能作为回退包。重新握手 MCP 0.4.0/13工具，核对 create_vibe_storyboard_v2、import_rendered_video_v2、expectedCanvasRevision、稳定 operationId 和原回执查询；旧工具明确返回替代提示。绝不直接热覆盖运行 bundle。
7. **灰度冒烟。** 先用批准的邀请测试账号/合成项目验证登录、个人/项目知识隔离、文档 CAS/历史/保护、图谱、Latest/Pinned、多文档输入和草稿。付费真实模型必须另外批准预算。当前邀请码只是注册准入，知识接口未具备按邀请码 cohort 的功能授权；真正生产功能灰度需服务端 cohort gate 和旧客户端能力校验先行获批实施，不能用隐藏菜单、URL或可伪造 cookie 充当授权。
8. **验收后开放。** 先执行故障停写/读取/回执演练，再由用户批准开放邀请 cohort；监控 CAS冲突、SQL锁等待、知识403/404、任务/对账积压、重复 retry/供应商请求、素材转存错误、插件最低安全版本与旧客户端写入。阈值按获批容量预算制定，本轮不擅设生产超时/并发/自动重试。监控不可用、任何越权/数据丢失/费用不明/重复供应商提交时立即停止写入，保留现场。

## 安全回滚

- **第一动作停写，保留读取。** 使用已验收网关规则冻结 HTTP 写入，MCP 单独 read-only，停止写 Worker 和旧客户端入口；记录 taskId/operationId/providerRequestId/账单与 revision。环境变量不是热开关，实际受控进程是否生效须验证；生产重启/切换仍需授权。
- **代码回退仅到安全兼容制品。** 回退包必须同时认识 Knowledge Node/版本字段、保留 CAS 与幂等、具备 Markdown 净化。没有这样的旧包时保留当前安全读取、关闭写入并向前修复；不能让旧前端全量保存省略新节点，不能重开旧直库 MCP。
- **数据库只向前。** 0045/46/47表、知识历史、回执、归档与快照全部保留；不降低 revision、不删除历史、不用旧整库备份覆盖发布后数据。内容恢复需逐项目/逐文档获批，生成更高 revision，并保存恢复前后来源和审计。
- **对象保留。** COMMIT不明或账单不明时保留对象和原操作 ID，不自动清理未引用对象；从备份恢复到新桶/隔离目录核对后，再审批指向修复。付费任务先查原供应商请求，不能靠新任务补发来“恢复”。
- **恢复写入再审批。** 根因已定位、修复制品经隔离验证、重复请求与授权测试通过、旧写者不可达、对象/版本/账单一致且监控可用；用户批准后才恢复。未满足条件维持只读，不自动进入 P2.5 开发或发布。

## 邀请灰度验收标准

- cohort 外用户的直接 API、跨项目引用、生成任务和重试均不能绕过服务端 gate；cohort 内仍需正常账号/成员权限，Operator不越权。现有用户是否纳入必须明确，邀请码 required 只影响新注册。
- 旧标签页读到新图后不能在缺少知识能力声明时进行全量保存；已保存草稿保留且显示明确升级提示。能力声明只用于协议兼容，不能替代权限。
- 文档/版本/附件权限和 Markdown 原文保真不变；图谱关系不生成工作流边；真实来源/账单验收通过，失败或回执不明时原操作可查询。
- 备份能恢复、迁移可重入、插件客户端升级有覆盖证据；停写演练覆盖 Web/MCP/Worker/知识/任务，读取与授权回执可查。未通过项不能靠扩大灰度人数绕过。
