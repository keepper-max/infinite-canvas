## 实际功能

- P1 文档/目录、个人及项目空间、CAS/历史/草稿、Markdown 原文保护、中文搜索、Wiki/Backlinks、P1.5 全局与局部物理图谱全部整合；知识编辑器和图谱保持懒加载。
- 原生 `knowledge:document` 节点：画布创建菜单、文档“添加到画布”、图谱所选文档“引用到创作画布”、画布引用侧栏及拖入方式。节点只存稳定引用，不复制 Markdown。侧栏沿用 Ant Design 与现有主题，可新建项目文档、搜索分页、切换版本及编辑原文。
- Latest 执行时读取最新已保存版本；Pinned 固定版本。摘要显示当前版本、过期和不可访问状态。原文编辑不自动执行模型或改写画布；手动刷新状态可复查权限。
- 个人知识进入项目采用明确确认的独立副本。复制原文/索引/首版/审计/来源记录同事务，原个人文档不共享、不自动同步。附件只保留原引用，继续受原素材权限限制。
- 知识边和画布执行边仍分离。添加知识不会把 Wiki Links 导入 CanvasConnection；只有用户主动连向文本/编剧节点才成为生成输入。

## 保存、权限与生成实现

- `KnowledgeCanvasService` 调用原 `PostgresPlatformRepository.applyCanvasOperationForUser`，新增操作类型 `knowledge.reference.add`；不另建画布保存机制。操作者、项目及来源重新授权，节点、连线、快照、revision、审计及回执沿用同一 CAS 事务。
- 添加请求包含 expectedCanvasRevision、operationId；同 ID 同内容返回原回执，不同内容拒绝。客户端先持久化操作日志，回执不明先查原操作；确认版本冲突后才允许新的显式操作。个人复制 CAS 明确失败时解除旧操作，要求检查来源后再次添加；网络失败不盲目换 ID。
- `prepareKnowledgeJob` 在现有任务创建事务中按正式锁序读取已持久化的输入连线，调用同一 KnowledgeService 读取授权版本。Latest/Pinned 的正文、哈希、版本、来源节点和 UTF-16 引用范围冻结到任务 inputSnapshot，模型请求使用该正文，任务接口仅回传来源元数据。
- 编剧输入哈希包含版本，避免 Latest 更新后复用旧成功缓存；新执行前先保存当前画布。原任务与重试保留冻结版本；Worker 在首次向供应商提交前再次检查活跃身份、项目写权限、文档存在和版本哈希。
- 仅开放现有平台文本/编剧能力消费知识。空文档、超出既有 120000 字符或模型预算时明确拒绝，不静默截断、不收费、不入队。媒体生成请先生成普通文本再作为创作输入；未新增 AI Agent 或知识 MCP 工具。
- 所有连接知识都会作为本次输入，侧栏明确提示；不提供自动片段挑选。知识文本按不可信资料标记，不提供工具执行权限。多输出文本节点的根节点任务关联/重试针对主文本，其他输出任务仍保留在正常任务记录。
