# 第 4 部分：任务系统与全局模型网关

## 目的

将所有真实生成从浏览器迁到后台 Worker，统一管理密钥、模型能力、参数、进度、重试和产物转存。

状态：`complete`（已通过本机隔离 Docker/PostgreSQL/Redis/MinIO 验收）

## 范围

- 建立 `model_catalog`、`model_capabilities`、`provider_routes`、`provider_configs`。
- 迁入现有 Token360 全局模型目录与 Seedance 模式适配，保留现有有效逻辑。
- 目录发现与人工能力覆盖表合并；内部模型 ID 与显示名分离。
- 建立 `workflow_runs`、`node_runs`、`generation_jobs`、`job_attempts`、`job_events`、`job_artifacts`。
- Redis/BullMQ 入队、Worker 执行、Provider 轮询/回调和结果转存 OSS。
- SSE 项目事件流，断开自动重连，查询接口作为兜底。
- 幂等键、重复提交保护、取消请求、失败重试、超时和并发控制。
- 参数过滤：文生、图生、首尾帧、多参考分别按能力表构造请求。
- 普通用户显示中文错误，管理员查看脱敏原始错误。

## 非目标

- 不做积分扣费。
- 不承诺所有目录模型都可用；只有能力表验证通过的模型开放给对应节点。
- 不在浏览器执行 Provider 请求。

## 重点风险

- 超时、轮询、重试和并发默认值会改变真实行为，实施前按环节说明并确认。
- 取消状态必须区分 `cancel_requested` 与 Provider 确认的 `canceled`。
- Worker 重启不能把已取消任务更新为成功。

## 已确认运行边界

- Worker 默认并发 2，可通过环境变量调整。
- 自动重试 2 次，即首次执行加重试总计最多 3 次。
- Provider 提交超时 60 秒，异步视频轮询间隔 5 秒，单任务最长运行 30 分钟。
- 取消先写入 `cancel_requested`，Worker 停止或确认 Provider 取消后才进入 `cancelled`。

## 验证

- 创建任务、入队、执行、SSE 进度、完成和资产版本写入。
- 重复点击只生成一个有效任务。
- Worker/Web 重启后任务恢复。
- 四种视频模式都只发送受支持参数。
- Provider 临时 URL 在过期前转存 OSS。
- 失败任务能单独重试，取消后不继续完成。

## 完成条件

- 页面关闭不影响任务；刷新后恢复进度和结果。
- 浏览器代码、存储、请求和日志中不存在真实 API Key。

## 回滚

- 新任务可暂停入队；旧浏览器直连只作为开发回退且生产默认关闭，不恢复密钥到浏览器。

## 本轮实现结果

- 已新增模型目录、能力覆盖、Provider 路由、任务、尝试、事件和产物迁移；事件序号由数据库串行分配。
- 已新增 BullMQ Worker、两阶段取消、三次总尝试、30 分钟总时限、任务幂等和刷新恢复。
- 已将内置文本、图片、音频和视频生成统一迁入服务端任务 API；生产构建会清除旧浏览器渠道密钥并隐藏直连入口。
- 已按 `t2v`、`i2v`、`flf2v`、`multiref` 分别编译参数；资产版本在 Worker 执行时校验项目归属并解析为临时地址。
- 已将生成结果转存对象存储并创建不可变资产版本；完成事件和节点同时保留任务 ID 与精确版本 ID。
- 本地 API 类型检查、20 项测试和构建通过；前端类型检查和构建通过。
- 隔离 Docker 环境完成注册与默认项目、模型目录、BullMQ Worker、SSE、幂等、四种视频模式、MinIO 转存、不可变资产版本和服务重启恢复验收。
- 集成验收发现并修复取消竞态：Worker 不再用运行态覆盖 `cancel_requested`，提交、轮询和转存阶段均会重新确认取消状态；运行中取消后稳定保持 `cancelled`。
- 自动三次尝试失败、最终可重试状态及手动重试成功已通过真实 Redis 队列验收。
