# 第 9 部分：生产发布编排与外部验收

## 目的

把第 8 部分已经完成的本地功能与安全边界整理成可重复、可审计、可回滚的生产发布流程。

## 范围

- 生产环境只读预检，不输出任何密钥值。
- Web 与 API/Worker 分别构建不可变提交标签镜像。
- 发布前自动创建并校验代码、环境、数据库、容器和镜像备份。
- 先迁移并切换 API/Worker，再切换 Web，失败时恢复上一版镜像。
- 发布后执行健康检查、外部访问和人工业务验收清单。
- 保存不含密钥的发布清单，支持按发布记录回滚。

## 非目标

- 本任务包不启用真实短信、支付和积分扣费。
- 未确认生产容量策略前，不擅自写入限流、日志轮转或告警阈值。
- 收到 `执行第9部分` 只实施并验证发布编排；修改 ECS 仍需要独立的 `部署 ECS` 指令。

## 执行步骤

1. 建立生产预检和脱敏发布清单。
2. 调整 Compose 镜像变量，使 Web 与 API/Worker 可按提交标签切换。
3. 补齐 GitHub Web/API 双镜像构建。
4. 建立带显式确认、备份验证、分阶段切换和失败回滚的发布脚本。
5. 建立按发布清单执行的手动回滚脚本。
6. 用临时环境变量完成脚本语法、Compose 解析、类型检查、测试和生产构建。
7. 更新生产手册和项目进度；等待独立部署指令。

## 完成条件

- 发布脚本缺少确认口令或必填配置时必须在改动服务前退出。
- 预检和发布输出不包含 `.env` 值或 API Key。
- Web 与 API/Worker 使用不同镜像，并能以 Git 提交号标记。
- 任何发布失败都保留备份路径和上一版镜像引用。
- 本地验证全部通过；生产灰度、外部冒烟和回滚演练在收到部署指令后完成。

## 回滚

- 代码改动可撤回本任务包提交。
- 生产回滚只切换到发布清单记录的旧镜像；增量数据库结构默认保留，不删表、不删列。
