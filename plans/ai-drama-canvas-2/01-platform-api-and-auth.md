# 第 1 部分：平台 API、账号与默认草稿空间

状态：`complete`（2026-09-09）

## 目的

在保留 Vite 前端的前提下增加独立 API 服务，为后续画布、资产和任务提供可信用户边界。

## 范围

- 建立 API 服务、Drizzle Schema 和 PostgreSQL 迁移目录。
- 建立 `users`、`sessions`、`projects`、`project_members`、`canvases` 基础表。
- 邮箱密码注册登录，Argon2id 哈希，随机 Session Token，HttpOnly Cookie。
- 接口：注册、登录、当前用户、退出、项目列表、项目读取。
- `ensureDefaultWorkspace`：新用户首次进入时只创建一个个人草稿项目和一张画布。
- 登录后进入最近画布；没有最近记录时进入个人草稿画布。
- 所有项目接口校验成员关系；同源 Nginx 反向代理，浏览器不跨域直连 API。

## 非目标

- 不做短信登录、OAuth、支付、积分扣费和团队邀请。
- 不迁移旧 IndexedDB 数据。
- 不接真实模型。

## 重点风险

- Cookie 的 Secure 策略需要区分本地开发与生产 HTTPS。
- 默认草稿创建必须幂等，并由数据库唯一约束保证不会重复。
- 所有按 ID 查询必须同时受用户成员关系约束，不能先查资源再在前端判断。

## 验证

- 注册、登录、退出、重复邮箱、错误密码和 Session 失效。
- 首次登录只创建一个草稿项目；多次登录不重复创建。
- 用户 A 无法读取用户 B 的项目与画布。
- API 容器重启后 Session 仍可从 PostgreSQL 恢复。
- 类型检查、认证单元测试、数据库集成测试和生产构建通过。

## 完成条件

- 新用户登录后直接进入画布，不出现强制创建项目页面。
- 第 2 部分可以安全地把画布数据绑定到用户和项目。

## 回滚

- 数据库迁移必须提供向下迁移或全库备份恢复说明；生产迁移前再次备份。
