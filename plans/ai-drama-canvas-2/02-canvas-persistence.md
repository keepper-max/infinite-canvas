# 第 2 部分：云端画布持久化与旧数据迁移

## 目的

将节点、连线、视口和快照从仅浏览器保存升级为服务端权威，并安全保留旧画布。

## 范围

- 建立 `canvas_nodes`、`canvas_edges`、`canvas_snapshots`。
- API：读取画布、事务保存画布、读取历史快照、恢复快照。
- 节点位置、尺寸、类型、`workflowKind`、metadata、端口数据结构化保存。
- 连线保存 source/target 节点、端口和引用角色。
- 使用画布版本号做乐观并发控制；保存冲突不能静默覆盖。
- 前端以服务器快照为权威，localForage 仅缓存最近成功快照和未同步草稿。
- 页面进入时加载服务器，断网时明确显示“未同步”。
- 旧 IndexedDB 迁移向导：预览、确认、上传、报告、失败回退。
- 迁移明确排除 API Key、渠道 URL、代理和 WebDAV 凭据。

## 非目标

- 不在本部分上传大媒体文件；只保存可迁移的画布结构和媒体待转存引用。
- 不实现资产版本和任务队列。

## 重点风险

- 当前节点 metadata 字段较自由，服务端需要严格校验但不能破坏插件扩展字段。
- 保存节流和冲突策略会影响用户操作，实际默认值在实施时先说明再确定。
- 旧媒体 Blob 不能作为普通 JSON 上传，需要在第 3 部分完成正式转存。

## 验证

- 移动节点、连线、缩放视口后刷新页面，状态完全恢复。
- 两个标签同时编辑时能检测版本冲突。
- 保存失败时本地草稿保留并显示未同步状态。
- 用户 A 不能读写用户 B 的节点、边和快照。
- 迁移失败不删除 IndexedDB 原数据，不上传旧密钥。

## 完成条件

- 服务器成为画布权威，刷新与服务重启不丢画布结构。
- 能为第 3 部分的媒体转存提供明确的画布资源引用清单。

## 回滚

- 保留旧 localForage 读取路径为只读迁移入口；云端写入异常时不覆盖本地旧数据。
