# 第 3 部分：OSS 资产与不可变版本系统

## 目的

让图片、视频和音频脱离临时 URL 与浏览器 Blob，形成可追溯、可切换、可恢复的统一资产库。

## 范围

- 建立 `assets`、`asset_versions`、`asset_links`、`trash_items`。
- 抽象对象存储接口：开发 MinIO、生产 OSS。
- 上传、下载、缩略图、元数据、校验值和文件归属校验。
- 每次上传或生成创建新版本，不覆盖旧文件。
- 主版本切换、版本比较、从旧版本继续生成、来源追溯。
- 角色、场景、道具、图片、视频、音频使用统一资产表，通过分类和 metadata 区分。
- 删除进入回收站；彻底删除由单独清理任务执行。
- 旧 IndexedDB 媒体经过用户确认后逐个转存，失败项可重试。

## 非目标

- 不在本部分运行真实 AI 生成。
- 不实现 FFmpeg 合成。

## 重点风险

- OSS 临时签名 URL 不能作为永久资产地址保存。
- 上传完成与数据库写入需要补偿逻辑，避免孤儿文件或空版本。
- 删除资产时必须检查画布、任务和其他版本引用。

## 验证

- 上传图片、视频、音频后刷新仍可读取。
- 切换主版本不改变旧任务所绑定的版本。
- 用户 A 无法读取用户 B 的对象存储文件。
- 临时 URL 失效后可重新签名访问。
- 回收站恢复有效；有引用的版本不会被误删。

## 完成条件

- 画布所有长期媒体均由资产版本 ID 引用，不依赖临时 Provider URL。
- 第 4 部分任务完成后可以安全写入新的资产版本。

## 回滚

- 数据库和对象存储分别备份；失败写入通过补偿清单处理，不批量硬删除。
